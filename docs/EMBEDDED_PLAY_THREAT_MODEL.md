# Embedded Play Phase 0B Threat Model

## Status and boundary

This document freezes security preparation only. Embedded Play Phase 0B and all player-visible behavior remain blocked pending independent Security and Release approval. The three policy modules are pure and test-only: they do not call Electron APIs, enumerate sources, access files, spawn or stop processes, open sockets, or provide runtime services.

## Platform posture

- Windows: video-only capture contract; audio is always off.
- macOS: disabled pending packaged-app consent validation.
- X11: experimental and independently gated.
- Wayland: external-only.
- Local-only: no GameDeck Live, WebRTC, relay, remote peer, or other network path.

Independent kill switches default off for capture, managed process control, and input injection. Enabling one must not enable another.

## Security invariants

Capture grants bind one active session to the exact sender and frame, a session epoch, trusted injected source-authority evidence, a one-shot source-registration receipt, the verified window handle and source identifier, video-only media scope, trusted session-bound action registration, a recent single-use action marker, an injected opaque grant identifier, bounded replay retention, and expiry of at most five seconds. Source authority evidence is verified by an injected authority against the exact session, epoch, sender, frame, handle identity, source ID, window kind, and video-only scope; evidence replay, source substitution, primitive handles, screen-disguised IDs, audio, and fallback claims fail closed without consuming capacity or advancing the trusted clock. Grant issue consumes the source receipt once and both issue and consumption reject caller-labeled source values. Consumption is atomic and one-shot. Replacement, expiry, session replacement, and explicit revocation produce stable reasons. Public status excludes grant, authority, and source receipt identifiers, paths, source IDs, sender/frame handles, and action markers.

Managed process policy accepts only exact expected canonical executable, core, configuration, and content identities proven inside their managed roots, with platform-explicit case/separator rules, no unresolved dot traversal, explicit reparse/symlink decision inputs, and exact receipt identity. Canonical path claims are accepted only through a branded policy created with an injected trusted verifier that binds each opaque one-shot evidence ID to the exact platform, raw path, canonical path, managed root, path kind, and reparse result; arbitrary tokens, replay, and raw-to-canonical substitution fail closed, and evidence is committed only after the entire launch contract succeeds. The approved platform, executable, core, configuration, content, install identity, receipt identity, and SHA-256 digests live in the trusted policy closure rather than the untrusted launch request. Request-authored expected paths or receipts are rejected, and canonical but unapproved substitutions fail without consuming canonical evidence. Receipt install and receipt IDs use bounded strong opaque tokens, while executable, core, configuration, and content digests must be exact 64-character SHA-256 hex values. The working directory is derived from the trusted canonical executable directory and must equal the managed runtime root. HOME and PATH are separate absolute canonical directory contracts tied to explicit managed roots; the launch environment is the exact minimal allowlist `HOME`, `LANG=C`, `LC_ALL=C`, and `PATH`, with no arbitrary inherited environment. A future Windows adapter may add a required system variable only through a separately documented fixed allowlist and canonical value contract. The launch contract is the fixed RetroArch form `--config <config> -L <core> <content>`; fullscreen is forbidden. Any future adapter must use `shell=false`, `detached=false`, and `unref=false`. Stop is a complete-tree state machine: graceful request, escalation after deadline, post-stop verification, and failure unless root, descendants, and handles are all gone. This module never reads the filesystem or controls a process.

Input protocol bounds serialized payload size, event count, rate, queue depth, total projected button state, and retained connection epochs. Each connection uses an injected opaque epoch bound to every message, and the active epoch counts toward the connection budget so direct reconnect cannot overrun retention. Sequence numbers increase monotonically within that epoch; acknowledgements report the highest processed sequence. Full button snapshots are authoritative, deltas are applied to a temporary projected set and fail closed before sequence/rate/queue mutation if the set would exceed the button cap, and release-all is explicit. The processing watchdog measures the age of the oldest queued work, resetting its baseline when an empty queue receives new work, so newly queued input after idle is not treated as stale while a genuinely stalled queue releases every button after 500ms. Reconnect requires a fresh epoch and authoritative resynchronization. Rate-window reset is an explicit elapsed-window decision, so repeated messages at the same timestamp cannot reset accounting. Queue overflow compacts pending deltas into the latest capped full snapshot so release events cannot be silently lost.

## Blocked work

No integration with `main.js`, `preload.js`, `src/*`, display-media handlers, Electron capture APIs, process spawn/kill, source enumeration, sockets, networking, runtime services, UI, flags, or player-visible behavior is authorized by this preparation.
